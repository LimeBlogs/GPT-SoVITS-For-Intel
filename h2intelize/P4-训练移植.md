## R2：`hps` 访问铁律

`GPT_SoVITS/utils.py:324` 的 `HParams` **没有 `.get()`，没有 `__getattr__`**。

```python

# ❌ AttributeError
```

**例外**：`s1_train.py` 的 `config` 来自 `yaml.full_load` → 普通 dict，`.get()` 可用。

## R3：Windows 必须 `num_workers = 0`（**最容易踩**）

`s2_train_v3_lora.py:136` 是 `worker_count = 4`，`s2_train.py:135` 是 `num_workers=4`。

Windows 的 DataLoader worker 用 **spawn** 启动，**会重新 import 主模块**。而 `s2_train.py` 在**模块级**有：

```python
hps = utils.get_hparams(stage=2)                                  # ← 内部 argparse.parse_args()
os.environ["CUDA_VISIBLE_DEVICES"] = hps.train.gpu_numbers...     # ← HParams 取值
```

worker 的 `sys.argv` 是 multiprocessing 引导参数，于是：

- `argparse` 报 `error: argument -c: expected one argument` → worker 被杀
- 或把引导代码当配置路径 → `FileNotFoundError`
- 或加载默认 `configs/s2.json` → **没有 `gpu_numbers`** → `AttributeError`

**Linux 用 fork 继承内存，所以没这问题；Windows 必有。**

```python
# s2_train_v3_lora.py:136
worker_count = 0 if os.name == "nt" else 4
```

```python
# s2_train.py:133-141
num_workers=0 if os.name == "nt" else 4,
persistent_workers=False if os.name == "nt" else True,
```

> ⚠️ `persistent_workers=True` 配 `num_workers=0` 会直接 `ValueError`，两个一起改。
> `s2_train_v3_lora.py` 已有 `if worker_count > 0: loader_kwargs["persistent_workers"] = True`，只改 `worker_count` 一处即可。

## 3.2 显存预算（bs=3，fp32）

| 项 | 估算 |
|---|---|
| net_g fp32 | ~0.8 GB |
| net_d fp32 | ~0.5 GB |
| 激活 + 梯度（bs=3） | ~3.5 GB |
| STFT 中间量 | ~1.2 GB |
| 上下文 + 碎片 | ~1.0 GB |
| **合计** | **≈ 7.0 GB** |

**8G 卡只有 1G 余量。bs=4 很可能 OOM。**

> 注意：fp32 比 bf16 多吃一倍显存。之前按 bf16 算的 6.2G 现在要上调。

## 3.3 OOM 时的降级顺序

```
1. batch_size 3 → 2
2. 关掉 tensorboard 的 histogram（省一点）
3. 设 PYTORCH_XPU_ALLOC_CONF=expandable_segments:True
4. 最后才考虑 segment_size（会改变训练语义，不推荐）
```

### 1b. `main()` / `run()`

```python
def _pg_backend() -> str:
    if _BACKEND == "xpu":
        return "ccl"                      # oneCCL，仅多卡；单卡不会走到
    return "gloo" if os.name == "nt" else "nccl"


def main():
    n_gpus = du.device_count(_BACKEND) if du.accel_available(_BACKEND) else 1
    want_ddp = bool(getattr(hps.train, "ddp", False))        # R2

    if n_gpus <= 1 or not want_ddp:
        run(0, 1, hps)                     # 单卡：不进 mp.spawn，不 init_process_group
        return

    os.environ["MASTER_ADDR"] = "localhost"
    os.environ["MASTER_PORT"] = str(randint(20000, 55555))
    mp.spawn(run, nprocs=n_gpus, args=(n_gpus, hps))


def run(rank, n_gpus, hps):
    use_ddp = du.accel_available(_BACKEND) and n_gpus > 1
    try:
        if use_ddp:
            dist.init_process_group(
                backend=_pg_backend(),
                init_method="env://?use_libuv=False",
                world_size=n_gpus, rank=rank,
            )
        _run(rank, n_gpus, hps, use_ddp)
    finally:
        if use_ddp and dist.is_initialized():
            dist.destroy_process_group()
```

```python
is_half = eval(os.environ.get("is_half", "True")) and du.supports_fp16_fast(du.default_device())
```

> `device` 若在 `is_half` 之后才定义，直接用 `du.default_device()` 内联，不依赖变量顺序。

**性能提示**：这 4 个脚本是「读音频 → 提特征 → 存盘」，batch 小。GPU 利用率常 < 30%，**直接设 `cpu` 可能更快**（避免反复搬运）。先用 xpu 跑，慢了再换。

# 7. 禁止事项

| # | 禁止 | 原因 |
|---|---|---|
| X1 | Windows 上保留 `num_workers=4` | worker 必崩（R3） |
| X2 | 用 `hps.xxx.get()` 或 `hps.train.gpu_numbers` | HParams 没有（R2） |
| X3 | 引入 bf16 分支 | 无收益且 STFT 会崩（R4） |
| X4 | 用 `batch_size: 32` | 第一 step OOM |
| X5 | 训前不改 `batch_size` | 同上 |
| X6 | 训练时用 `ipex.optimize()` | 改写结构，checkpoint 不兼容 |
| X7 | 改 `segment_size` 省显存 | 改变训练语义 |
| X8 | 没跑满 100 step 就说"跑通了" | 伪报 |
| X9 | 一次 commit 混多个 T | 无法回滚 |
| X10 | 在 WSL / docker 里做 | 本文件假定原生 Windows |

# 8. 停止条件

| 情况 | 动作 |
|---|---|
| D7 报 `argparse` / `gpu_numbers` | 停，R3 没改对 |
| D7 报 `ModuleNotFoundError: tools` | 停，R1 垫片没加 |
| 第一 step 就 OOM | 停，`batch_size` 降到 2 |
| `RuntimeError: expected scalar type ... but found ...` | 停，1j 的 `.to(net_d_dtype)` 漏了 |

| s1 报 Lightning XPU 错误 | 退 `accelerator="xpu"` → `"cpu"`，记录在 commit |
| 训练中途 hang 无日志 | 停，`$env:PYTORCH_XPU_LAUNCH_BLOCKING="1"` 重跑定位 |
| 任何验收改 3 次不过 | 停，报告 traceback |
