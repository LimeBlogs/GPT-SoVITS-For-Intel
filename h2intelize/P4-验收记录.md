## 3. 与 P4 文档的偏差（都已验证，不是猜的）

1. **v3/v4 LoRA 在 `batch_size=3` 会硬崩**：
   `AssertHandler::printMessage` + 进程退出码 `-1073741819 (0xC0000005, ACCESS_VIOLATION)`，
   发生在第 2–3 step（不是 Python 异常，抓不到 traceback）。
   **`batch_size=2` 稳定跑完 192 step，`batch_size=1` 稳定跑完 384 step。**
   → 对应文档 §3.3「OOM 降级顺序」，但这里是驱动级崩溃而不是可捕获的 OOM，
   所以 `configs/s2.json` 的 `batch_size` 定为 **3（v2 GAN 实测可用）**，
   **v3/v4 走 LoRA 时请手动降到 2**（WebUI 里就是「batch_size」那一栏）。
2. **s1 需要 XPU 垫片**：`pytorch-lightning 2.6.6` 的 accelerators 只有 `cpu/cuda/mps/xla`，
   没有 `lightning_fabric.accelerators.xpu`；`accelerator="gpu"` 抛
   `MisconfigurationException: No supported gpu backend found!`。
   按文档 §4d「gpu → xpu → cpu」逐级退，最后一级 CPU 能跑（实测 5 epoch），
   但本阶段额外写了 `tools/lightning_xpu.py`（最小 `XPUAccelerator` +
   `SingleDeviceStrategy(xpu:0)`），**s1 已经实跑在 XPU 上**。
   ⚠️ 若以后 Lightning 自带 XPU accelerator，代码会自动走官方分支（`lx.lightning_has_xpu()`）。
3. **s1 用 `configs/s1longer-v2.yaml` 而不是 `s1longer.yaml`**：
   `s1longer.yaml` 是 v1 模板（`phoneme_vocab_size: 512` + 需要 `3-bert` 特征），
   v2/v3 数据（732 符号表）会越界。WebUI 也是这么分的（`webui.py:616`）。
4. **Rich 进度条在 GBK 控制台会崩**：重定向输出时
   `UnicodeEncodeError: 'gbk' codec can't encode character '\u2022'`，
   训练其实已经跑完，只在 teardown 抛。已在 `s1_train.py` 里按 stdout 编码自动关掉进度条。
5. **命令行直跑没人建断点目录**：`s2_train.py` / `s2_train_v3.py` 的 `my_save` 会
   `FileNotFoundError: [WinError 3]`（WebUI 会提前 `makedirs`）。已改成脚本自己建。

## 4. 必须知道的实现细节

### 4.1 R3（Windows worker）确实是「必崩」级
三个 s2 脚本 + `AR/data/data_module.py` 全部改成 `num_workers=0`，
且 `persistent_workers`/`prefetch_factor` 只在 `num_workers>0` 时传
（否则 `ValueError: persistent_workers option needs num_workers > 0`）。
`s1` 的 val dataloader 按文档用 1。

### 4.2 精度
`_PRECISION` 在本机恒为 `"fp32"`（`du.supports_bf16()` 因
`has_bfloat16_conversions=False` 返回 False）。bf16 分支保留但从不执行，
`amp.make_scaler()` 在 XPU 上恒 `enabled=False`，`amp.autocast_ctx()` 返回 `nullcontext`。
STFT 走 CPU（`Aten Op fallback from XPU to CPU`）属于预期行为。

### 4.3 s1 的「step」语义
`AR/models/t2s_lightning_module.py` 是 **manual optimization**：
`automatic_optimization=False`，且
```python
if batch_idx > 0 and batch_idx % 4 == 0:
    opt.step(); opt.zero_grad(); scheduler.step()
```
即**每 4 个 batch 才更新一次参数**（上游原始设计，本次未改）。
本机 5 epoch × 25 batch = **125 batch 迭代 / 30 step**，checkpoint 名字里是
`epoch=4-step=30.ckpt`（Lightning 用 optimizer step 计数）。
